---
name: visual-panels-to-video
description: Turning one or more approved VISUAL panels sheets (the 4K panel-grid images built by the `visual-panels` skill) into the FINAL video. Takes the sheet images, an optional references manifest (characters / products / settings to lock identity), and (when available) the INTERACTIVE storyboard JSON (the authority for per-clip timing, per-shot action, dialogue, SFX and music). Composes the cinematic per-shot video prompt for each clip, renders one video per CLIP: a clip is a group of consecutive panels (e.g. panels 4–7), and a single sheet can hold several clips (see each sheet's `metadata.clips`), with each clip's duration driven by the interactive storyboard when present, generates a single music track when needed, and assembles every clip back-to-back on a timeline into one continuous video. Use whenever you have approved panel sheets and need the rendered video (e.g. Step 4 of the create-video workflow). Pairs with `visual-panels` (its upstream) and `timeline-assembler` (which it delegates assembly to).
---

OUTPUT stage: `visual-panels` produced the approved 4K sheet(s); this skill **composes the video prompt AND renders** each clip, then stitches all into the final film. Assembly mechanics (track layout, fps/aspect inheritance, music ducking, transitions, subtitles, preview handoff) are delegated to **`timeline-assembler`**: read its SKILL.md before assembling, don't re-derive.

## 🛑 STEP 0: RECOVER + READ THE INTERACTIVE JSON FIRST (MANDATORY, before any `generate_video`)
The sheet is NOT the script, the storyboard JSON is. Never infer the scene from sheet pixels when a `sourceStoryboard` exists (reported bug: hallucinated "vending machine" for a man-on-a-sofa storyboard).

3. NEVER skip to a raw `generate_video` off pixels + invented prompt; compose FROM the JSON (STEP B), shot by shot.
4. Fall back to sheet pixels ONLY when `inspect_creation` returns no `sourceStoryboard`. Never ask the user to name the project.

## STEP A: Enumerate the CLIPS and resolve each clip's duration
**A sheet is NOT a clip.** `visual-panels` packs multiple clips per sheet in **`metadata.clips`**: `[{ clipIndex, shotIds, panels, durationSec }, …]`. Read every sheet's `metadata.clips` (via `inspect_creation`), concatenate, sort by global `clipIndex` → render plan. **One `generate_video` per CLIP**, in `clipIndex` order across ALL sheets, NOT per sheet. Fallback (old sheets, no `metadata.clips`): whole sheet = one clip.

**Duration range: read from the tool, never hardcode:** `get_tool_info("generate_video")` → `duration` schema (typical whole seconds [4,15] + `"auto"`; trust the tool). Use `D_min`/`D_max`. Resolve per clip, priority: (1) **`clip.durationSec`** (PREFERRED): clamp to `[D_min,D_max]`; with the JSON cross-check == sum of its `shotIds`' `shot.duration`; (2) no JSON → sheet pixels: sum per-panel timecodes for total `S`, or use banner total (`PART K: … (<n> frames · <S> s total)`), clamp `S` to a whole second in `[D_min,D_max]`; (3) neither → `D_max` AND surface uncertainty via `print`.

NEVER hardcode `duration: 15` when the storyboard says otherwise. State per-clip durations before rendering (*"3 clips: PART 1 → 14 s, PART 2 → 10 s, PART 3 → 10 s"*). ⚠ **The storyboard total overrides any duration in the task/brief** (task "60 s" but storyboard sums 48 s → video is 48 s; don't pad/stretch/add filler). Sole exception: explicit hard-target ("must stay exactly 60 s") → refit.

### ⛔ Fail-fast: a single CLIP > 15 s is malformed (a sheet may exceed 15 s, fine)
Sanity-check EACH clip (`durationSec` or summed `shot.duration`). Any clip > 15 s (or no `metadata.clips` AND whole sheet's shots sum > 15 s) → upstream chunking bug; don't silently drop shots (*"hizo los 15 s pero solo de una parte"* bug). STOP: *"Clip `<clipIndex>` sums to `<X>` s but a rendered clip caps at 15 s. Please re-build the sheets with `visual-panels`: its Chunking step splits shots into ≤15 s clips I'll then render and concatenate."* Never auto-compress/truncate.

## STEP B: Render one `generate_video` per CLIP (a group of consecutive panels, e.g. 4–7 → ONE video), never per-panel, never per-sheet, SEQUENTIALLY with frame-chaining
> 🛑 BEFORE the first `generate_video`: activate `seedance-2-0` (see "MANDATORY FIRST ACTION"). Don't skip to a self-written brief.

Unit = **clip** = a GROUP of consecutive panels (`metadata.clips[].panels`). `[4,5,6,7]` → ONE video for panels 4–7. NOT per panel; NOT per sheet (a 12-panel sheet may be 3 clips → 3 videos, e.g. 1–4/5–9/10–12). Cite the range: *"follow ONLY panels 4–7 of `Image 1`; ignore other panels (other clips)."*

**Several panels can be ONE continuous take (one CUT): animate THROUGH, no cut.** Two cases, same handling: (a) a camera-move shot's 2-3 keyframe panels (share `shotId`) = start/middle/end of one move; (b) consecutive shots flagged `noCutBefore` (or sharing `number`) = glued plano secuencia. Both → cite ALL panels, move smoothly, NO internal cut. A real cut falls ONLY where the JSON is NOT glued.

**Render SEQUENTIALLY, not parallel**: the previous RENDERED VIDEO carries real motion/lighting/pose + world-state (broken/dirtied/moved in K-1) so the seam inherits camera energy + momentum and K can't reset to pristine; and you sanity-check before committing. Flow K ≥ 2: wait for K-1, verify `savedTo` exists; include K-1's path in `referenceVideos` (alias `prev_clip`), keep OWN sheet + prior sheets + character/product refs; render, wait, repeat. IMMEDIATE predecessor only (chain 1→2, 2→3); don't pile earlier clips (last sheet covers older history). Clip 1: no `referenceVideos` unless the user gave an external opening reference.

> 🛑 **MANDATORY: ATTACH REFERENCES ON EVERY CLIP** (text-only clip drifts). Order: (1) panel sheet(s): current `sheet_part_K` ALWAYS, plus for K ≥ 2 every prior `sheet_part_1…{K-1}`; (2) reference images: character/product/location refs this clip needs, from the `references` manifest AND storyboard `references` arrays (root+scene+shot), resolving `@handle`s; (3) previous clip (K ≥ 2): K-1 in `referenceVideos` as `prev_clip` (→ `Video 1`). The tool REJECTS (`success:false`) if the prompt cites `Image N`/`Video N` not attached. **Pre-call self-check EVERY call:** highest `Image N` cited == `referenceImages` count; same for `Video N` ↔ `referenceVideos`. A ref not attached (didn't resolve / clip 1) → don't cite it; describe in plain words. Never invent a citation.

Per CLIP (global `clipIndex` order) call `generate_video` with:
- **`prompt`**: per "Per-clip prompt construction"; MUST cite the clip's `panels`.
- **`referenceImages`**: entry 1 = clip's OWN sheet, alias `sheet_part_K` (or `storyboard` for a single-sheet storyboard); on sheet ≥ 2 also every prior sheet; then append `references` entries `{ alias, path }`. **Order is load-bearing**: position 1 IS `Image 1`. Prompt cites POSITIONS not aliases. Decide order before writing.
- **`referenceVideos`** (K ≥ 2 ONLY): `[{ alias: "prev_clip", path: <K-1's savedTo> }]` → `Video 1` (independent counter). Omit for K=1. IMMEDIATE predecessor only.
- **`duration`**: CLIP's resolved value (`clip.durationSec`), whole second in `[D_min,D_max]`. NOT hardcoded, NOT the sheet total.
- **`aspectRatio`**: target platform (9:16 Reels/TikTok/Shorts, 16:9 YouTube/web, 1:1 or 4:5 Instagram). MANDATORY; sheet stays 16:9 (reading surface), model reframes. 16:9 clip in a 9:16 timeline = black bars.
- **`quality: "high"`**.
- **`withAudio: true`**: ALWAYS (default `false` → omitting = silent = hard failure). Controls DIEGETIC sound (SFX/dialogue/voiceover/ambient), NOT music. Exclude music ONLY via the closing Audio line, NEVER via `withAudio: false` (kills SFX/voices). Only `false` for a deliberately fully-silent clip (essentially never).
- **`saveTo: <directory>`**.

> **FAILURE →** ONLY THEN use the built-in brief below (self-sufficient). Failure = plugin not fully installed; don't tell the user to install separately. Enhancement, not dependency. Don't call `generate_video` until you've activated `seedance-2-0` or confirmed it unavailable.
> Why: it encodes Seedance conventions → compact dense prompts (≈40–110 words), anti-slop wording, one intention per shot, IP-safe rewrites, continuation anchored to the previous clip's REAL last frame/state. **Division of labour:** it shapes WORDING + cinematography; THIS skill owns STRUCTURE + the tool call (positional `Image N`/`Video N` + canonical order, panel-range citation, aspect/duration, frame-chaining, plumbing). Keep citations `Image N`/`Video N` (even though it documents `[Image1]`-style); fold its craft INTO the 5-part shape.
> **Feed it THIS clip's material** (JSON = script, seedance = phrasing): shots' `action`, `shot`/framing/angle, `camera` movement, `dialogue`, continuity-matrix row(s) for this clip's panels, resolved `duration`, target `aspect`, reference plan (which panels on which `Image N`, `prev_clip` as `Video 1`). It never invents beats or drops continuity/dialogue.

Prompt = a **director's brief**, natural/structured/flowing, no banners, caps-shouting, verbatim blocks. Transcribe the JSON's per-shot `duration`, shot/framing/angle, camera movement, `action`, sound (authority over the sheet's tiny labels). **Reference syntax = positional** (`Image 1`…, `Video 1`…; images & videos separate counters). Aliases = auto-legend/logs only; prompt cites POSITIONS. Canonical order (decide first): current sheet `sheet_part_K` → prior sheets → identity refs (character, product, location) → `prev_clip` as `Video 1`. Runtime auto-prepends a one-line legend, don't repeat.

5-part shape:

**1. References block + format line.** State each ref's role by position; NAME this clip's panel range (*"follow ONLY panels 4–7 of `Image 1`, in order; ignore the rest"*; camera-move keyframes → *"panels 5–7 = start/middle/end of one continuous push-in, don't cut"*). Pattern: *"Use `Image 1` as authoritative shot blueprint (exact beats, framing, pacing). Do NOT render the sheet: ignore borders, panel frames, text labels, duration tags, headers, swatches, chrome. Use `Image 2`+ as authoritative `<subject>` reference: match face, build, hair, wardrobe/paint, lights, badge exactly."* Then: *"Create a cinematic `<duration>`-second `<aspect>` `<type>` video [of `<subject>`]."* Aspect = target platform, not the sheet's 16:9.

**2. `Video 1` continuation block (K ≥ 2 ONLY, ~80–110 words).** BOTH halves non-negotiable: temporal continuation (no world-state reset) AND photos-beat-`prev_clip` identity (no drift propagation): *"`Video 1` is PART {K-1}. PART K continues DIRECTLY from its last frame: same camera energy, character momentum, lighting, world-state. Anything broken/moved/consumed/dirtied at its end stays that way at t=0, don't reset. For identity, the photo refs (`Image 3`, `Image 4`…) beat both the sheet and `Video 1` (a generated approximation that may drift: hairline, wardrobe shade, paint tone, prop detail); pull identity from photos. Hierarchy: reference photo > sheet > `Video 1`."* Immediate predecessor only; older history covered by their sheets at `Image 2…{K-1}`. Omit for K=1.

**3. Style brief (1 dense comma line)** from storyboard `style`/`lighting`/`aspect`, pushed into motion terms: **3D/family** = animation principles (squash & stretch, anticipation, follow-through), warm practicals, volumetric light, readable silhouettes; **Live-action/cinematic** = film grammar (handheld, Steadicam, crane), motivated lighting, subtle performance, naturalistic ambience; **Anime** = speed lines, impact frames, snap zooms, limited animation on holds, sakuga for peaks, particles, light bloom; **2D/hand-drawn** = smears/multiples, moving holds, consistent line weight, painterly backgrounds, parallax, fluid secondary motion; **Stop-motion/claymation** = handcrafted clay/puppet, visible material texture, miniature sets, tungsten warm light, soft shadows; **Other** = adapt (a creative-director line, not a checklist). Example: *"premium hospitality brand film, warm coastal daylight, white-and-gold palette, clean editorial framing, subtle 35mm texture, smooth transitions, no on-screen text."*

**Continuity lock (short paragraph right after): when JSON has `synopsis` and/or `continuity`.** Premise in one line, then `continuity` rules as ABSOLUTE constraints the clip must never "fix" (negatives the model won't infer), e.g. *"Premise: the boy can't reach the high Pepsi button, so he stacks cans to climb. Hard rules every shot: button stays mounted high & out of reach until he's up on the cans, never lower it or make him taller; cans stay intact, never crushed; same machine, same can colours."* ~40–70 words; the single best guard against "unreachable became reachable" / "step-object destroyed" drift. Omit only when JSON has neither field.

**Per-tool tailoring** (when `targetGenerator` given): Seedance = character animation + lip-sync (expressive beats + dialogue, moderate camera); Kling = dynamic camera (orbits/crane/push-ins); Sora = cinematic composition (framing, lensing); Veo = long coherent sequences (let shots breathe); Runway/Luma/Hailuo/Wan/Higgsfield = model-agnostic conservative camera unless signalled.

**4. Numbered CUTS: one CUT per continuous TAKE.**
> 🛑 FAITHFUL TRANSCRIPTION, NEVER INVENT A SHOT (#1 rule). CUTs come ONLY from THIS clip's JSON shots, in JSON order. A CUT = one continuous TAKE: most shots are their own take, but a camera-move's keyframe panels AND a `noCutBefore`-glued / shared-`number` run collapse into ONE take. Split into takes (real cut ONLY where NOT glued), emit EXACTLY one CUT per take: no add/drop/reorder/invent/split/merge. Each CUT's direction IS its shot('s) `action` (+ `continuity`/`dialogue`/`sfx`). Inputs: (1) JSON = script, (2) this clip's panels on the CURRENT sheet = look. Terse `action` → render exactly, only tighten physical mechanics; never invent a plano ("se inventa algunos planos" bug). Before writing, state *"this clip has N takes → N CUTs"*, then match.

**Build the take↔panel(s) map FIRST** (NOT "shot N = panel N"; a CUT can own several panels). Walk shots in JSON order alongside `panels` ascending: STATIC shot → ONE panel, own CUT; CAMERA-MOVE shot → its 2-3 keyframe panels (same `shotId`) as ONE CUT; `noCutBefore`-glued run → panels accumulate onto the SAME CUT as the previous shot. Result: 1:1 take↔CUT; each CUT's panel ref = ALL panels its take consumed. Ex A: `[static,move,static]` over `[4,5,6,7]`, middle 2-panel move → CUT 1→4, CUT 2→5-6, CUT 3→7. Ex B: 3-shot plano secuencia, shots 2&3 `noCutBefore` over `[1,2,3]` → ONE CUT → 1-3. (Σ assigned panels MUST equal the clip's count.)

CUT HEADER LINE with description BELOW it, never inline:
```
CUT 5 (0:04 - 0:05)
CU low-angle, slow dolly-in. Ruby's gloved hand brushes red dust, revealing a green sprout; focus racks from hand to leaf. Use panel 5 of `Image 1` as the visual reference for this cut. SFX: faint suit-radio static, soft regolith crunch.
```
Each entry: **(1) Header `CUT N (START - END)`, own line**: CUMULATIVE clock within the clip from `0:00`; each cut spans its TAKE's summed `duration`; N START = running total of prior takes, END = START + this take; format `M:SS`, decimal ONLY when fractional (`0:01.5`); the LAST cut's END MUST equal the clip's resolved duration (else mis-summed: redo). **(2) Panel reference (ALWAYS):** *"Use panel X of `Image 1` (the sheet) as the visual reference for this cut."* Several panels (camera-move keyframes / glued take) → cite ALL: *"panels 5-7 of `Image 1` as start, middle, end of this single continuous take, no cut."* Single most important fidelity line, never omit. **(3) Framing + camera**, shot size (CU/MS/WS/…), angle, movement (dolly-in, orbit, static…) in cinematic verbs at the START. **(4) Scene direction**: blocking/staging/action/acting beat, tight (one sentence; refs carry the look, prose drives motion). **🔬 Nail PHYSICAL MECHANICS** (model renders words literally, improvises wrong details for vague ones): singular over loose plural ("inserts a single coin held between thumb and forefinger", NOT "inserts coins"); name grip/finger/posture; concrete identifiers ("button 2 of 16", "the red suitcase on his left"), never interpretable ("his floor"); one mechanical step per shot. **🎬 CONTINUITY / raccord (most-neglected): carry established state into EVERY shot's prose or the model drops it.** Once a non-default state is set (standing ON the stacked cans, a melted hole, soot on face), every later shot where it holds MUST restate it: *"still standing on the two stacked cans, he presses the Pepsi button"*, not just *"presses the Pepsi button"* (renders him back on the ground). ⚠️ The `action` may be USER-written & incomplete: track state yourself, restate carried-forward state even where that shot's `action` dropped it; never invent a new EVENT, only re-inject established state. When the shot carries `continuity` ({ characters, objects }; legacy `state`) tracking is done: it IS authoritative; transcribe both columns instead of re-deriving. Neighbour contradiction (crushed here, stood-on next) = self-contradictory source → render the physically coherent reading `synopsis`/LOCK imply and surface the conflict; never animate the impossible state. **(5) Dialogue** (if any): `Character: "<line>"`. **(6) SFX**: inline at the end.

JSON absent → treat each panel as its own shot. Cuts fall WHERE THE JSON CHANGES SHOT.

**🎯 CAMERA VIEWPOINT**: non-default angle (rear/side/POV/overhead/low-angle): state inline AND negate the opposite (models default to a front hero shot; the reference anchors LOOK not framing). rear → *"Camera behind, rear only, taillights visible, driving away. No front, no headlights."* POV → *"First-person POV, subject's hands visible at bottom; the subject is never shown."* side/over-shoulder/top-down/low-angle: same. **🎬 Causal order**: state advances chronologically; never aftermath before cause (no wrecked room before wrecking, no empty plate before eating); shot numbers ARE the causal order.

Don't re-describe visual STYLE per shot (sheet + style brief carry it) nor subjects' appearance (named refs carry it). Don't reproduce sheet chrome: no in-panel labels/frame numbers/duration tags/banner text bleed. Only permissible text = genuine in-WORLD text physically part of a depicted object (product label, street sign), from subject `referenceImages`, never the sheet.

**5. Closing audio line**: one line from the audio plan. Single-sheet or music baked in: *"Audio: Diegetic sound only, natural ambience, environmental foley, subject-driven sound."* Multi-sheet with separate music track: *"Audio: Diegetic SFX, dialogue and ambience only, music is on a separate timeline track, not part of this clip."* Shots still include inline SFX; this line covers music. **`withAudio: true` is a tool param, NOT prompt text**; NEVER `withAudio: false` to keep music out (silences SFX/voices).

**Word-count targets:** K=1 ≤6 shots → ~250–400 words; K=1 7–10 shots → ~400–600; K ≥ 2 → +~80–110 for the `Video 1` block. Don't pad, but give every shot enough motion direction to differentiate it.

## STEP C: Music track (single, full-length, only when needed)
Audio plan calls for music AND **≥ 2 sheets** → ONE separate track (per-clip music thumps every boundary; independent renders can't keep a continuous melody across seams): ONE `generate_audio`, `type: "music"`, `duration: <total = sum of all clip durations>`, `prompt` from the type's music brief + tone. Single-sheet (one clip, no seams) → music inside the clip render is fine, skip. Voiceover-only / SFX-only → no music, skip.

## STEP D: Assemble the timeline (concatenate every clip into one video)
Follow `timeline-assembler`.
1. **Always `create_timeline` a NEW timeline**: one fresh per video; NEVER reuse/append/overwrite. Descriptive `name` + target `aspectRatio`; do NOT pass fps/width/height (inheritance). Keep the returned `timelineId`.
2. **V1: concatenate clips in order, back-to-back, each clip's OWN duration** (cumulative cursor, no uniform 15 s slots):
   ```
   cursorMs = 0
   for clip in clips (in sheet order):
       add_clip_to_timeline(track="V1", path=clip.path, startMs=cursorMs, durationMs=clip.durationSec * 1000)
       cursorMs += clip.durationSec * 1000
   ```
   `add_clip_to_timeline` auto-detects each clip's audio stream, do NOT pass `hasAudio`.
3. **A2: music** (if STEP C): one clip at `startMs: 0`, `durationMs: totalMs`. **Duck ONLY where it competes with voice, from actual audio, not reflexively:** voiceover/dialogue → duck to ≈ −28 dB (`set_clip_volume(<musicClipId>, { change: { gain: 0.04 } })`, or `volumePoints` for speaking stretches); NO-voice sections (action beat, intro/outro, wordless montage, SFX-only) → do NOT duck (music is the main audio; ducking sounds empty). Agent decides from whether voice is present. See assembler's "Audio mixing levels".
4. (Optional) subtitles for tutorial/explainer per the assembler's "Subtitles" matrix.
5. **Hand-off: ALWAYS end by showing the TIMELINE.** `show_result({ resourceType: "timeline", timelineId })` (preview) → `render_timeline` → final artifact = `show_result({ resourceType: "timeline", timelineId })` (holds the finished video; user plays/tweaks/re-renders). MAY also `show_result({ resourceType: "video", path })`, but the timeline show is mandatory and last. Full sequence in the assembler's "The render hand-off."

Final length = sum of per-clip durations (= storyboard total when present). Concatenation is timeline-only: NEVER `ffmpeg concat` or any glue tool.

## Continuity formula (Seedance-class) and reference hygiene
**Reference hygiene: pass CLEAN panel crops, never the raw sheet, when the model accepts several references.** The whole sheet (gutters, borders, chrome) contaminates the render: grid lines bleed as banding/striping (reported: stripes across a character's hair). Extract each clip's panels with `extract_panel` (clean crops, no gutters/numbers) as blueprint images, plus separate character/prop refs. Fall back to the whole sheet only when slots can't fit crops, then keep the "ignore the sheet chrome" negative.

**Panels are ACTION REFERENCES, never start frames: say it in the prompt.** A panel = a representative moment WITHIN its cut (often mid-action), not the first frame. (1) input-side: never pass a panel/sheet as `startFrame` (only frame-chained final frames from the previous clip qualify); (2) prompt-side, per cut + once globally: *"the panels of Image 1 are reference stills of a moment WITHIN each cut, NOT starting frames: begin each cut naturally before its reference moment and flow the motion through it."* Without this, Seedance-class freezes the panel as the literal first frame.

**Multi-shot continuity formula:** (1) identical subject nouns in every cut (SAME short noun phrase; re-describing re-casts them); (2) same reference set for every clip (same images, same order); (3) lock lighting + set phrasing verbatim across cuts & clips (copy, don't paraphrase); (4) max ~5 camera setups per generation (exceed → split into two frame-chained calls); (5) **FRAME-CHAINING = the plano-secuencia formula (anchor-and-extend):** extract the FINAL FRAME of clip N, pass as FIRST frame/anchor of clip N+1 (provider `startFrame`/`lastFrame`, else first reference image + "continue exactly from this frame"): preserves set/wardrobe/light/positions better than text; (5b) **PREVIOUS CLIP AS VIDEO REFERENCE** (when the model accepts video refs, e.g. Seedance-class, check capabilities first): final frame = join POINT, previous VIDEO = DYNAMICS (pacing, actor movement, camera cadence, lighting in motion); every clip after the first, attach it AND state its role: *"the reference video is the IMMEDIATELY PRECEDING clip of this same film: continue its story directly, matching pacing, camera language, lighting, set and the exact state of every character at its end; do NOT copy its shots or repeat its action"* (without the role sentence, models re-enact it); no video ref → frame-chaining (5) is the fallback; (6) **true plano secuencia:** describe as ONE shot with a single continuous camera move (never CUT blocks), one clip; over the cap → split at a motivated moment and frame-chain (5) → invisible cut; (7) **one master audio bed:** music OFF the clips (separate track), only diegetic SFX per cut.

## Voice consistency across clips (read once)
With `withAudio: true` voiceover is per clip; reference-to-video models match voice to the visible character, so the same character ref across sheets gives high-but-not-guaranteed consistency. If voice audibly drifts, fallback: `withAudio: false` on every clip (silent), generate ONE TTS pass of the whole script via `generate_audio` with a fixed `voice`, lay as a second audio track. Trades lip-sync precision for identical voice, use only when drift shows.

## Iteration
- **Clip re-roll:** `generate_video` again for that clip, same references, revise ONLY the affected per-shot directions (point 4); keep references block, `Video 1` block, style brief, audio line identical. K ≥ 2 prev_clip still points at K-1; if K-1 was re-rolled, propagate its NEW path.
- **Total duration change:** re-resolve per-CLIP durations (STEP A); relative weighting usually scales, don't uniformly scale unless the user said so.
- **Target generator change:** swap the per-tool tailoring paragraph and re-render; shot grammar stays, only camera language shifts.

## Don't (terse checklist; each detailed in full above)
- Hardcode `duration: 15` (STEP A owns timing).
- Search disk for the storyboard JSON (STEP 0 / INPUTS: metadata is the only auto-recovery; missing → sheet pixels, never an unrelated JSON).
- Compress a >15 s CLIP by dropping shots (STEP A fail-fast; a SHEET may exceed 15 s, a CLIP never).
- Render one clip per panel or per sheet, one per **CLIP** (STEP B).
- Copy sheet chrome, or burn ANY text into the video (point 4; spoken lines are AUDIO).
- Drop the JSON's per-shot direction (point 4; only STYLE + appearance aren't re-described).
- Add cuts the JSON doesn't have (point 4; glued runs = one CUT).
- Flip the viewpoint, or break causal order (point 4: force viewpoint + negate opposite; state only advances).
- Reset world state between clips (STEP B: PART K opens in PART K-1's end state).
- Bake music into per-clip renders for ≥ 2 sheets (STEP C), or duck music reflexively (STEP D: only under voice).
- Ship a silent clip / use `withAudio: false` to drop music (STEP B).
- Render 16:9 for a vertical target (pass the platform `aspectRatio` every call).
- Concatenate outside the timeline, reuse/append a timeline, or finish without `show_result`-ing the TIMELINE (STEP D).
